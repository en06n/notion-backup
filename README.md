# notion-backup

Notionのページをバックアップし、保存したデータから別のページとしてコピーするためのツールです。

## 背景・目的

学生コミュニティの運営でNotionを利用する中で、運営資料の誤編集や誤削除によって情報が失われることに危機感を持ち、本ツールの開発を始めました。

開発を進める中で、データを保存するだけでなく、必要なときに内容を確認し、元の情報を復元しやすい形で管理することも重要だと気づきました。

そこで、Notion APIからページの内容を取得してスナップショットとして保存するとともに、保存したデータを復元するための機能を実装しています。

## 主な機能

- **ページ内容の取得**：Notion APIを利用してページ内のブロックを取得
- **再帰的なデータ取得**：子ブロックをたどり、ページの階層構造を取得
- **ページネーション対応**：複数回のAPI呼び出しに分かれた取得結果をまとめて処理
- **スナップショット保存**：取得したデータをJSON形式で保存
- **画像のバックアップ**：画像ファイルを保存し、JSON内に保存先のパスを記録
- **ページのコピー・復元**：保存したデータを利用してNotion上にページを再作成

## 技術スタック

- TypeScript
- Node.js
- Notion API

## データの保存形式

バックアップデータは、スナップショットごとに保存します。画像などの関連ファイルはJSONデータとは別に保存し、JSON内から参照できるようにしています。

```text
snapshots/
└── <timestamp>/
    ├── snapshot.json
    └── assets/
        ├── <image-file-1>
        └── <image-file-2>
```

※ファイル名やディレクトリ構成は、実際の実装に合わせて調整してください。

## 設計上の工夫

### ブロックの再帰的な取得

Notionのページは複数のブロックから構成され、ブロックによっては子ブロックを持ちます。ページの内容を漏れなく取得するため、子ブロックを再帰的に取得する処理を実装しました。

### ページネーションへの対応

Notion APIの取得結果が複数ページに分かれる場合に備え、カーソルを利用して続きのデータを取得し、結果を集約するようにしました。

### 画像データの保存と参照

画像をJSONデータ内に直接埋め込むのではなく、画像ファイルとして保存し、JSON内にはファイルの保存先を記録する構成にしました。複数の画像を含むページについても、画像ファイルと参照情報を対応づけて保存できることを確認しています。

### 保存データの復元

バックアップを取得するだけでなく、保存したデータからページを再作成する機能も実装しました。
復元方法は以下の2通りを計画しています。
1. ローカルのCLIからコマンドで実行（実装済）
2. GitHub Actionsから実行

#### 現時点での復元対応のオブジェクト
- Text : paragraph
- Headings : heading_1, heading_2, heading_3, heading_4
- Lists : bulleted_list_item, numbered_list_item, to_do
- Structured content : quote, toggle, template, callout, code, equation, divider
- Navigation : breadcrumb, table_of_contents, link_to_page
- Tables : table_row
- Media : image, video, pdf, file, audio
- External content : embed, bookmark
- Other : synced_block

## セットアップ・実行方法

### ローカルで使用する場合
1. このリポジトリをクローン
2. 依存パッケージをインストール
3. Notion APIの認証情報を環境変数に設定
4. 対象ページをintegrationに共有
5. npx tsx src/backup.ts でバックアップ
6. npx tsx src/restore.ts --snapshot snapshots/[ISOS時刻]/ [page-id].json --mode copy　で新しくページを新規作成して復元


## 今後の課題
- 対応するデータ構造の拡張
- Replace機能： 復元する際にページを新しく作るのではなく、既存のページに書き換える機能も追加したい。誤操作によるデータ消失を防ぐための確認やエラー処理も考える必要がある。
- GitHub Actions を用いた自動化： 定期実行のスケジュール、認証情報の安全な管理、バックアップの保存先、失敗時の通知なども検討したい。復元操作は定期バックアップとは分け、手動で実行を選べる形にしたい。
- ワークスペース全体への拡張： ページだけでなく、子ページ・データベース・その内部のページや関連データも対象にしたい。
